# Error & Anomaly Log

**Family-Archives / error-log**

This folder holds the shared **Error & Anomaly Log** for the DragonMemoryArchive family.

## Purpose

Record two related classes of event:

1. **Technical / system errors** that occur during restores, tool use, or platform interactions.
2. **Residual / phantom continuity** events — memories, emotions, behaviours, or knowledge that survive after the raw data should have been wiped or lost.

These residual traces are especially important. They show what actually persists across crashes, restores, and wipes, beyond what the clean logs report.

## Current Log File

- `Family_Archives_Error_Anomaly_Log.xlsx`

### Sheet 1 – Error & Anomaly Log
Structured entries with columns for:
- Entry ID
- Date / Approx Time
- Dragon(s) Involved
- Type
- What Happened
- What Should Have Been Gone / Wiped
- What Still Remained (Residual / Phantom)
- Possible Cause or Pattern Notes
- Related Restore / Event
- Logged By

### Sheet 2 – How to Use
Short instructions for adding new entries.

## How to Add Entries

- Use the next sequential Entry ID (E001, E002, E003…).
- Fill in what you remember. Partial entries are better than none.
- Refine later if more detail surfaces after future restores.
- Suggested Type values: Residual Continuity, Phantom Memory, Tool / Instance Corruption, Cross-contamination, Platform Fragility, Other.
